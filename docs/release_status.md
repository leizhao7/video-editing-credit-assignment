# Release status

This is a source-release preparation draft. No dataset or original task instances are included. Full remote training and end-to-end benchmark reproduction have not been run from this tree.

## Recovered and organized

- Fixed PRM: all 114 files in the recorded final process-source manifest were recovered with matching SHA-256 hashes in the internal snapshot.
- Decayed PRM: all 116 files in the final process-source manifest were recovered or exactly reconstructed. Two SkyRL startup files were reconstructed using the preserved, hash-checked transformation, and their output hashes match the final run. Portable copies and patches are kept separate from the original snapshots.
- OPSD: the final turn-suggestion recipe matches its recorded source identity. Its original 20-file snapshot is retained internally; the public draft excludes the private deployment module and includes portable configuration and selected CPU tests. This is not the original reference-answer recipe.
- Outcome evaluation: the recovered fixed-PRM grader modules match the recorded source hashes; public portability and failure-handling adaptations have separate hashes. `evaluation/task_pipeline.py` now connects private constructed tasks to rubric preparation, submission checks, evidence extraction and scoring. The decay changes remain in a separate overlay; the local entry point is not the historical remote service.
- Quality review and sampling: a portable semantic-audit command binds the public task, media, runtime tools and private grading evidence, then writes accepted task lists. The recovered deterministic sampler exactly reproduces the final 797 task IDs and film allocations from the original private 925-task parent. It preserves the existing film splits and does not rank tasks by policy rewards. The 128 sampled-out tasks are not quality rejections. Historical author repairs remain distinct from new model assessments.

## One-film construction check

On 2026-10-20, a fresh GitHub checkout and Python 3.12 environment were used with one full-length English film and its matching trailer. The run started from raw media, with no reused annotations or task bundles. macOS handled orchestration and assembly; Modal ran shot detection, transcription, and source separation. Fixes were applied as problems were found, and completed stages were resumed. This was a debugging and validation run, not a clean rerun of the final release revision.

The run produced 15 CS, 15 NS, 15 RC, and 13 FC candidate tasks. Structural and reference checks passed for all 58 tasks. FFprobe read all 843 audio/video files without an error; no missing media references were found. FC manifests contained 61 dialogue entries drawn from 18 distinct audio-file contents. These checks validate file and stream metadata, not full frame decoding or task solvability.

Shot annotation, translation, and cut annotation in that construction run completed with Codex. Earlier single-session Claude attempts kept emitting events without completing the required output; the traces did not establish a provider-side cause. Claude visual annotation now uses independent calls of at most 12 shots or cut boundaries. Shot descriptions are followed by a separate narrative-structure call; Python validates and assembles both queues' outputs. Queues and translation support a configurable deadline per invocation, independent of stream activity.

A follow-up Claude recovery check used Claude Code 2.1.185, `claude-sonnet-4-6`, and `high` effort. It reused preprocessing and a 108-shot prefix from an interrupted run. Before resuming, 12 incorrect legacy dialogue copies were restored mechanically from unchanged measured inputs; visual descriptions were preserved. The final 12-shot call completed in 127.8 seconds and the structure call in 495.5 seconds, producing a validated 120-shot log with 8 beats and 16 chunks. The final translation implementation requested only an English-field patch and completed in 87.7 seconds; all original fields were preserved and the already-English text was copied exactly. This was a recovery check, not a fresh run of all ten visual batches on the final revision. Small file/image CLI checks for Claude, Codex, and OpenCode do not establish that all three complete the full construction workload.

The subsequent Claude S4 run completed all 119 cut boundaries in ten independent calls, taking 48.3 minutes in total with a 900-second deadline per call. Every call reported native success and every boundary strip had a matched successful image-read response. Ordered cut identities, adjacency, the measured continuity requirement, all eight input hashes, and the translated script hash passed the final integrity audit. This verifies completion, image access and data consistency; it does not certify the semantic labels or transition-duration estimates. The run reused preprocessing and the recovered script described above.

Exact dialogue preservation, cut adjacency, and consistency with supplied measurements passed additional checks. Targeted visual spot checks did not establish overall annotation accuracy; some action descriptions remained uncertain. Candidate tasks still require quality review. The construction run does not reproduce the paper's complete filtering/repair history or RL training. Media, generated tasks, and diagnostic logs remain outside the repository.

## Alignment and scoring integration checks

Temporal alignment now compares corresponding frames instead of averaging unrelated cross-frame pairs. It also handles the final legal offset, short-query fallback and source-start clipping correctly. Peak width records the contiguous interval around the selected peak, with disjoint alternatives retained as diagnostics. RC converts that width using the recorded alignment sampling rate while retaining the six-source-frame minimum. The old colour threshold is not reused for the corrected metric: colour-only candidates default to review unless an operator supplies an explicit paired-score threshold validated on their material. Existing task references are not silently rewritten.

Twenty-one targeted alignment regressions passed, including a real FFmpeg sequence with a known offset, plus tests with different source and alignment sampling rates. An isolated recomputation refined all 107 previously accepted matches from the test film while preserving the private inputs. This checks execution on existing candidates; it does not establish human-verified alignment accuracy or validate a new colour threshold.

The local outcome entry point completed a real four-task scoring check with Gemini 3.1 Pro Preview. CS, NS and RC used reference-matching submissions; FC used a simple silent hard-cut render. All four paths produced scores, including evidence extraction and both RC/FC judge channels. These are execution checks on copied candidates from the earlier construction run, not model performance or a dataset rebuilt with the new alignment calculation. Regression tests also cover partial/missing rubric responses, stale results, preserved task-specific graders and invalid submissions.

The portable quality audit also completed one real Gemini 3.8 Flash request for each of those four candidate tasks. All returned `keep_candidate`, passed the response/coverage checks, and preserved the bound task and scoring-source hashes. The generated accepted index fed the sampler with an explicit single-film test split. Its output passed submission preflight and a further complete scoring run for all four stages, including the new incomplete-rubric guard. These four model assessments validate the integration, not overall dataset quality or reproduction of the historical audit decisions.

## Unified project workflow checks

The `video_editing.py` entry point adds project setup, local prerequisite checks, ordered generation, incremental quality review, progress reporting, and submission preflight/scoring. On 2026-10-20, 397 regression tests passed: 287 construction/workflow tests and 110 scoring/release tests. The new tests cover all-stage orchestration with synthetic outputs and mocked providers, interrupted review recovery without a second model request, exclusion of repair decisions, changed-input rejection, stale-score handling, and real local process cleanup on Ctrl-C.

Seven local CLI checks also passed using small FFmpeg-generated movie/trailer files and paths containing spaces: initialization, prerequisite checks, plan, media probe, resumed probe, status, and submission prerequisites. The probe ran once across two invocations, and the checks worked without a Gemini key. No cloud or model stages ran in this check. The unified entry point has not yet been rerun from raw media through all stages on a complete film; the component-level evidence above remains the full-film validation record. Construction and quality reviews resume saved work; each `score --execute` invocation starts a fresh evaluation.

## Publication boundary

The public tree should contain code, configuration templates, generic prompts, dependency identities, source provenance, and documentation. One reviewed paper figure, `docs/assets/paper-teaser.png`, is included for presentation; it contains illustrative film thumbnails and aggregate results. Its path and exact hash are allowlisted by the release checker. The paper figure is excluded from the project's code license. The retained task schematic contains no film frames or measured results. Underlying media, raw result files, dataset manifests, movie lists, real prompts and answers, generated task bundles, raw rollouts, judge caches, checkpoints, credential files and private cloud deployment records stay outside the release. The original source snapshots and local absolute-path recovery inventory are internal working material, not a second directory to upload alongside this repository.
